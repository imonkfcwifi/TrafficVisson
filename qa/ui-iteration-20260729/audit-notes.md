# TrafficVisson 실제 Electron UI 재감사

- 감사일: 2026-07-29
- 기준 화면: Windows Electron 소스 앱, `1280×720`
- 시각 기준: `Pretendard와 리퀴드 글래스 디자인/uploads/pasted-1785143633633-0.png`
- 비교 증거: `15-reference-vs-final.png`

## 냉정한 초기 판정

초기 화면은 기능은 많았지만 컨셉 이미지의 시각적 위계를 제대로 옮기지 못했다.

1. 같은 크기의 KPI 카드가 반복되어 무엇을 먼저 봐야 하는지 불분명했다.
2. 8~10px 한글과 짧은 line-height 때문에 설치형 프로그램이 아니라 밀도 높은 MVP처럼 보였다.
3. `overflow: hidden`, 한 줄 말줄임과 고정 높이가 겹쳐 라벨링 진행 영역, 분석 요약, 검토 근거에서 실제 문장이 잘렸다.
4. 가져오기 소스 탭의 `네트워크 폴더`, `영상 링크`가 좁은 칸에서 줄바꿈됐다.
5. 한글 문장에도 mono 폰트가 섞였고, 배지의 line-height가 낮아 글리프 상하가 답답했다.
6. 웹 페이지를 다시 창 안에 넣은 듯한 장식과 균등 카드 반복이 실제 데스크톱 업무 흐름보다 강했다.

## 적용한 디자인 원칙

- SUIT Variable 2.0.5 전체 글꼴을 앱에 포함해 오프라인 한글 렌더링을 통일했다.
- 외부 창 모양을 흉내 내는 프레임 없이 Electron 자체 창을 제품 표면으로 사용했다.
- 홈의 첫 카드를 넓은 주 KPI로 만들고 나머지는 보조 카드로 축소해 비대칭 위계를 만들었다.
- 반경 18px, 옅은 경계와 얕은 그림자, 저채도 유리 표면을 공통 토큰으로 통일했다.
- 기본 본문을 11~12px 이상, 핵심 질문을 16px로 올리고 line-height를 1.3~1.4로 확보했다.
- 문서 전체와 각 `.screen`의 스크롤을 없애고, 사건 목록·영상 작업 목록처럼 길이가 변하는 데이터 영역만 내부 스크롤로 남겼다.
- 라벨링 설명은 3줄을 온전히 표시하고 네 응답 버튼과 하단 진행 상태를 같은 화면 안에 유지했다.
- 분석 요약은 상태·제목을 한 행에 재배치해 글자를 줄이지 않고 고정 카드 안의 잘림을 제거했다.
- 검토 하단 근거 행을 204px로 확보해 마지막 `추출 트리거` 행까지 표시했다.

## 수치 검증

- 모든 최종 화면에서 `documentElement.clientWidth === scrollWidth === 1280`
- 모든 최종 화면에서 `documentElement.clientHeight === scrollHeight === 720`
- 각 `.screen`은 `1180×612`이며 자체 수평·수직 문서 스크롤이 없다.
- 라벨링의 네 응답 버튼은 모두 `46px` 높이이며 화면 경계 안에 있다.
- 라벨링 하단 진행 패널의 하단 좌표는 `.screen` 하단 좌표 `680px`와 일치한다.
- 분석 요약 카드의 이전 초과 높이는 상태·제목 행 재구성 후 제거됐다.
- 사건·분석 작업 목록의 스크롤은 가변 데이터용 의도된 내부 스크롤이다.
- 최종 `win-unpacked`에서도 `SUIT Variable`이 로드됐고 document와 `.screen` overflow는 0이었다.

## 현재 판정

컨셉 이미지를 그대로 복제한 금융 대시보드는 아니지만, 그 이미지의 핵심인 차분한 액체 유리 표면, 비대칭 위계, 얇은 선, 낮은 채도, 검은 주 행동 버튼과 넉넉한 한글 행간을 TrafficVisson의 실제 업무 정보 구조에 맞게 옮겼다. 최종 화면은 브라우저 목업이 아니라 실제 Electron renderer와 실제 로컬 브리지 데이터를 사용한 상태다.
